# Diátaxis: A Framework for Documentation

**Diátaxis** is a systematic approach to organizing documentation created by Daniele Procida. It addresses the fundamental problem that documentation often tries to serve multiple conflicting purposes in a single document, resulting in confusion for both readers and writers.

## The Four Documentation Types

Diátaxis divides documentation into four distinct types based on two axes:

| | **Studying** (Learning) | **Doing** (Working) |
|---|---|---|
| **Practical** | **Tutorials** | **How-to Guides** |
| **Conceptual** | **Explanations** | **Reference** |

### 1. Tutorials

**Purpose**: Teach through learning by doing

**Characteristics**:
- Hands-on, practical lessons
- Assume user is a beginner
- Teach essential concepts through examples
- Build confidence through completion
- Should always succeed

**Example**: "Getting Started with DevDocs AI"

### 2. How-to Guides

**Purpose**: Show how to accomplish specific tasks

**Characteristics**:
- Goal-oriented, problem-solving
- Assume basic familiarity
- Address real-world use cases
- Provide working solutions
- Focus on practical results

**Example**: "How to set up OAuth with GitHub"

### 3. Explanations (Reference)

**Purpose**: Deepen understanding through conceptual discussion

**Characteristics**:
- Theory-focused, informational
- Explain why things work that way
- Provide context and relationships
- Can be technical or philosophical
- Educate and illuminate

**Example**: "Understanding the Diátaxis Documentation System"

### 4. Reference

**Purpose**: Enable quick lookup of facts

**Characteristics**:
- Accurate, complete, precise
- Organized for scanning (API docs, parameters, schema)
- Neutral, factual tone
- Not for learning from scratch
- Should be exhaustive in scope

**Example**: "API Reference Documentation"

## Key Principles

1. **Separation of Concerns**: Each type serves a distinct purpose and audience need
2. **Clarity of Intent**: Writers know exactly what they're writing and why
3. **User Navigation**: Readers can quickly find what they need
4. **Consistency**: Documentation follows predictable patterns

## Implementation Benefits

- **For Writers**: Clear structure reduces decision-making; easier to write focused content
- **For Readers**: Know what to expect from each section; easier to find needed information
- **For Projects**: Higher quality, more maintainable documentation; reduced redundancy
- **For Quality**: Systematic approach catches gaps and overlaps

## Structure in DevDocs AI

This project uses Diátaxis to organize its documentation:

- **Tutorials**: Get started with the platform, basic workflows
- **How-to Guides**: Specific tasks (authentication, project creation, doc generation)
- **Explanations**: Architecture decisions, system design, core concepts
- **Reference**: API documentation, database schema, configuration options
